# Local-first / workflow-as-asset positioning

VaultRun’s product stance for agent workflows:

1. **Local-first** — sandboxes, audit HMAC, missions, and cost data stay on the operator’s infra (no VaultRun SaaS).
2. **Workflow as asset** — a successful tool sequence should be saveable, inspectable, verifiable, and replayable — not trapped in chat logs.
3. **Complementary surface** — Flowd covers local file-workflow observation; VaultRun covers sandboxed execution + owned mission assets ([flowd.html](../../site/flowd.html)).
