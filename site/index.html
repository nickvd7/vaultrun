Open source · self-hosted

Let AI agents run code — without handing them your machine.

VaultRun is a self-hosted sandbox for AI agents. Every command runs in an isolated container on your own infrastructure — network off by default, every action signed in an audit trail. Works with Claude, Cursor, OpenAI and local models via MCP.

Why

    
Agents that can act need somewhere safe to act.

    
Once an agent can run commands, the question isn't whether it will run something it shouldn't — it's what happens when it does.

    

      

        
without Agent on your host

        
    
          
  • Shell access with your user's permissions and credentials
    • 
          
  • Open network: anything it reads, it can send somewhere
    • 
          
  • No reliable record of what actually ran
    • 
          
  • Runaway loops eat your CPU and your afternoon
    • 
        

      

      

        
with VaultRun Agent in a sandbox

        
    
          
  • Throwaway container per session, non-root, all capabilities dropped
    • 
          
  • Network off by default; allowlist per session when you need it
    • 
          
  • Every action HMAC-signed and queryable
    • 
          
  • CPU, memory and timeout limits per session
    • 
        

      

    

  






  

    
How it works

    
One API between your agent and the blast radius.

    
Your agent calls VaultRun instead of a shell. VaultRun decides, isolates, runs and records.

    

      
01 / connect
Point your agent at VaultRun
Use the MCP server with Claude or Cursor, the OpenAI-compatible gateway for local models, or the Python and Go SDKs.

      
02 / contain
Policy check, then a sandbox
A pluggable policy hook (OPA-ready) decides what may run. Allowed commands go through the Docker exec API — never a shell string.

      
03 / record
Signed trail, verified result
Every step lands in an HMAC-signed audit log. Optional checkpoints and sealed evidence assert exit codes, output and files before you trust the result.

    

  






  

    
Quickstart

    
Running locally in five minutes.

    
Pick how you want to start. Everything runs on your machine; nothing phones home.

    

      

        

          
          
          
          
        

        
sh
git clone https://github.com/nickvd7/vaultrun
cd vaultrun
cp .env.example .env   # set MASTER_API_KEY
make up                # API + Postgres + Redis + dashboard
make bootstrap-key     # prints your first vr_… key
curl http://localhost:8080/health
{"status":"ok"}
# dashboard → http://localhost:3000

        
python
# pip install vaultrun-sdk
from sandbox_sdk import Client

client = Client("http://localhost:8080", api_key="vr_…")
s = client.create_session(image="python:3.12-slim")
client.upload_file(s.id, "script.py", open("script.py", "rb"))
r = client.run(s.id, command="python", args=["script.py"])
print(r.stdout)

        
go
import (
    "fmt"
    vaultrun "github.com/nickvd7/vaultrun/sdk/go"
)

client := vaultrun.New("http://localhost:8080", "vr_…")
s, err := client.CreateSession(ctx, vaultrun.CreateSessionOptions{
    Image: "python:3.12-slim"})
if err != nil { return err }
run, err := client.Run(ctx, s.ID, vaultrun.RunOptions{
    Command: "python", Args: []string{"script.py"}})
if err != nil { return err }
if run.Stdout != nil { fmt.Println(*run.Stdout) }

Security model

    
Paranoid defaults. Honest limits.

    
Here's what VaultRun protects against, and where you should add more isolation.

    

      

        
    
          
  • 1
    No shellCommands go through the Docker exec API as argument arrays — no string interpolation.
    • 
          
  • 2
    Locked-down containersNon-root, all Linux capabilities dropped, workspace path-traversal checks.
    • 
          
  • 3
    Network offDisabled by default; per-session iptables allowlist when a task needs it.
    • 
          
  • 4
    Bounded resourcesCPU, memory and timeout limits per session.
    • 
          
  • 5
    Tamper-evident auditEvery action HMAC-signed. API keys stored as SHA-256 hashes. Optional sealed verify evidence digests.
    • 
          
  • 6
    Opt-in reachAWS, database, host-filesystem and OpenJEV/Jev tools are off until you enable them — no ambient credentials.
    • 
        

      

      

        
Threat model at a glance

        

          
Agent runs a destructive commandcontained only the session container is affected

          
Agent tries to exfiltrate datablocked network off unless allowlisted

          
Fork bomb / runaway loopbounded CPU, memory and timeout limits

          
Someone edits the audit logdetected HMAC signature breaks

          
Container escape via a kernel bugadd a layer Docker shares the host kernel — run with gVisor or Kata for untrusted workloads

MCP server

    
53+ tools. Two transports. Any agent.

    
Paste one snippet into Claude Desktop or Cursor, or run the HTTP transport for OpenAI and custom agents. Click a group to see its tools.

    

      

        
        
      

      
claude_desktop_config.json
{
  "mcpServers": {
    "vaultrun": {
      "command": "/path/to/vaultrun-mcp",
      "env": {
        "VAULTRUN_BASE_URL": "http://localhost:8080",
        "VAULTRUN_API_KEY": "vr_your_key"
      }
    }
  }
}

      
sh
MCP_TRANSPORT=http \
MCP_AUTH_TOKEN=your-secret-token \
VAULTRUN_BASE_URL=http://localhost:8080 \
VAULTRUN_API_KEY=vr_your_key \
./vaultrun-mcp
# POST /mcp — JSON-RPC 2.0, Bearer your-secret-token
